## Deferred / unresolved

- Pact 1 `UiV1:603` uses `MultipleDiyController`, command type 02 and
  `AbsMultipleController.getProType:19-20` A1 writes. Runtime A1 DIY is not
  implemented. Do not send modern A3 merely because RGB is 15/01.
- `SubModeColor` is the legacy 0B path. No legacy runtime codec is introduced
  here; full legacy payload, multipart framing, readback and recovery require
  their own qualification. Preserve unknown legacy selectors as bytes.
- Pact 10/{1,2} is registered by the app; runtime remains an experimental
  candidate pending exact-device qualification.
- Physical mapping, effect family/palette/variation authoring limits, Painted,
  Workshop and scene payload variants require exact-product qualification.
- Generated readback preserves Kelvin and gradual values even when controls
  are unavailable. Application recovery must retain those values without
  treating restoration as fresh observation. Synthetic tests verify software
  parsing/reuse; they do not establish physical behaviour.

## Protocol API

Common command/query builders, command/status parsers, static semantic builders,
scene/music selection, A3 parsing, ACK helpers and `expectations_from_packet`
accept keyword-only `profile: ModelProfile | None = None`. An explicit effective
profile controls grammar selection; otherwise existing `model` callers use the
registry. Codecs are structural: `require_profile_packet(packet, profile)` and
the existing application capability checks remain the authorization boundary.
For unresolved/legacy context retain the shared command grammar but restrict
`command_operations` to power/brightness, read only supported bootstrap domains,
and disable effect authorization. No SKU-specific command branch is required.

Pact 1 with qualified modern RGB may additionally declare operation `static`:
the generated `command_write.is_static` recognizes only 15/01, 15/02, 15/03.
It does not authorize scene/music/DIY selectors, A3 uploads or unknown static
operations. Power/brightness-only fallback remains available independently.

Boolean APIs (all accept keyword-only effective `profile`):

- `build_boolean_control(control, enabled, model)` writes a strict Python bool.
- `build_boolean_control_query(control, model)` queries `gradual` or `limit`.
- `parse_boolean_control(generated, model) -> dict[str, bool]` returns only
  declared controls from matching register replies. Unknown values raise
  `ValueError`; unrelated frames/disabled controls yield `{}`. AA05's flag and
  ordinary command ACKs cannot confirm a register write. Query authorization
  uses `boolean_controls` independently of ordinary `read_domains`.

## Upload ACK and selector contract

H6102 reuses the shared ACK syntax based on its own reachable controllers,
not H617A product policy. `AbsControllerNoEvent4Multi.b:36-38` and
`.onResult:100-102` check absolute byte 2 for zero; the `WithSub` subclass
`:12-15` moves status to byte 3. Protocol/opcode matching at `:84-87` leaves
music byte 2 opaque. Existing event-based DIY and music consumers agree.
`h617a_command_ack.ksy` covers ordinary 33 and A3 DIY/scene status at byte 2,
and A3/41 music status at byte 3. Negative results are false, mismatched
subtypes/ordinary replies are not upload confirmation. Same-subtype delayed
ACK ambiguity remains; no transaction identifier is invented.

The application's Advanced selector 402 and exact native selectors 501–507
use existing A3/02 layered grammar and shared 33/05/04/u2le activation. Tests
parse every compiled exact-model seed through the shared scene root and check
subtype 02 ACK selection; exact seed/catalogue authorization belongs to the
application (`docs/h6102-application-findings.md`).
