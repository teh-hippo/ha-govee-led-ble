# H6199 Pact 1 Restriction

A positively observed advertisement identifying H6199 Pact **1/1** selects a
partial profile.  Power control/readback, whole-strip RGB, brightness writes,
and main firmware and hardware identity queries remain available.  The legacy
RGB writer uses mode selector `0x0b`, RGB, zero Kelvin and whole-strip mask
`0x7fff`.  Brightness writes map percentages to the legacy register range
`20..254`; `0xfe` is the maximum brightness value, not a query sentinel.
The profile does not claim colour or brightness readback; it remains optimistic
across those writes.  Segments, colour temperature, music, scenes, video and
effect uploads remain disabled.
Unsupported notifications cannot install state or supply recovery evidence.
The light remains excluded from Effect Studio's device list.

HW `1.00.01` does **not** identify Pact.  Unknown Pact retains shipped model
behaviour for compatibility; that behaviour is unqualified, not proof of Pact 2
wire compatibility.  An absent/malformed advertisement does not erase a known
Pact restriction.  A later explicit Pact 2/1 advertisement restores the normal
model profile, subject to its existing firmware/identity gates.  Profile changes
discard incompatible retained control state rather than promoting it to fresh
observations.

Shared logical H6199 commands retain capability checks and optimistic
expectations.  The outbound transform re-encodes brightness and RGB through
the exact-model [speculative wire schema](../tools/ble/kaitai/speculative/h6199_pact1_wire_write.ksy);
it does not add a second command parser or authorise other operations.

These app-derived writes remain candidates pending independent official-app
captures at known brightness percentages and owner qualification.  Broader
hardware revisions and status readback remain unqualified.  The semantic guard
permits only power, brightness and whole-strip RGB at the physical write boundary.
No hardware-version heuristic, firmware change or effect upload is introduced.
